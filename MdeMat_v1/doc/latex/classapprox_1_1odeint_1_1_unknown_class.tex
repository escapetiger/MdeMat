\doxysubsection{Detailed Description}
Backward Differentiation Formula integrator. 

Abstract base class for ODE integrators.

Implements multi-\/step BDF methods (e.\+g., BDF2, BDF3) for solving ODEs of the form\+: d(\+M\texorpdfstring{$\ast$}{*}u)/dt = L\texorpdfstring{$\ast$}{*}u + S where M is a mass operator, L is a linear operator and S is a source term. Any of these terms can be empty. For mass operator, it means it reduces to an identity. For linear and source term, it means they vanish from the equation. BDF methods use multiple previous time steps to achieve higher-\/order accuracy and are A-\/stable, making them suitable for stiff problems.

Provides a common interface and shared functionality for all ODE integration methods. This base class manages solution history, timeline operations, and linear system solving infrastructure. Concrete integrators must implement the abstract methods for specific integration schemes.

We focus on the following ODEs of the form\+: d(\+M\texorpdfstring{$\ast$}{*}u)/dt = L\texorpdfstring{$\ast$}{*}u + F(u) + S where M is a mass term, L is a linear term, F(u) is a nonlinear term, and S is a source term. Any of these terms can be empty. In particular, M = \mbox{[}\mbox{]} means the mass operator reduces to an identity operator; \{L, F, S\} = \mbox{[}\mbox{]} means they vanish from the equation.

The contribution of mass operator M is determined by the physical simulation framework.


\begin{DoxyItemize}
\item In the Eulerian framework, M is space-\/only so that it can be represented by a unique static matrix.
\item In the Semi-\/\+Lagrangian framework, M is time-\/dependent. The LHS mass term is forced to be a unique static matrix as in Eulerian framework. However, the RHS mass term should be updated as time evolves. In particular, M is a matrix under periodic boundary conditions, while M is a pair formed by a matrix and a vector under Dirichlet boundary conditions. 
\end{DoxyItemize}

Update the solution history with a new solution. 

Shifts the existing solution history and adds the new solution at the most recent position. For multi-\/step methods, this maintains the required number of previous solutions. For single-\/step methods, simply stores the current solution.
